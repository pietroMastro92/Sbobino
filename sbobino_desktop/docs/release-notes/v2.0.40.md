## Sbobino 2.0.40

### Fixes

- Intel Conda runtime dependencies that name an exact library inside the payload can now retain a portable dylib identity. Relocation still rejects ambiguous, escaping or unverifiable reconstructed paths instead of guessing by basename.
- Conda prefix relocation can invalidate ad-hoc signatures without changing load commands. Those identity-less signatures are repaired; unsigned code remains visible as unsigned, and invalid real or unknown signing identities are refused before any payload mutation.
- The POSIX diarization helper reserves stdout for a single JSON result. Python and native-library diagnostics, including late finalizer messages, go to stderr; result parsing and the Windows output path remain unchanged.

- Stopping a live Whisper session now reports a worker crash that occurs during the interrupt wait and preserves the captured audio for recovery. Normal SIGINT stops remain successful.
- Companion pairing and AI stores explicitly unlock their profile leases when ownership ends, including storage-opening failures. Shutdown still drains active sessions before releasing ownership; restart tests no longer contend for OS-assigned ephemeral client ports.
- The release generator recognizes universal LLVM-bitcode objects from the official Python framework as data instead of trying to rewrite them as dylibs. This fixes the exact `python.o` failure in the unpublished 2.0.38 candidate.
- Universal Mach-O load commands are queried explicitly for every architecture, avoiding host-dependent omissions on Intel runners. Libraries embedded from the build machine are sanitized recursively before packaging, including their own dependencies and rpaths.
- Conflicting host libraries with the same basename now stop the repair during planning, before any file changes. Runtime replacement checks canonical containment, including intermediate symlinks, and local build roots are refused inside the checkout before creation.
- Companion pairing status distinguishes a missing record from an invalid profile layout on Windows, whose filesystem error mapping differs from macOS. Rust lint regressions are fixed without suppressions or changing the supported-device behavior.

- Packaging a release candidate on a hosted macOS runner no longer stages the Pyannote runtime in the system temporary directory. The generator now creates every staging directory from an explicit `mktemp` template under `TMPDIR`, so the workflow's `TMPDIR="$RUNNER_TEMP"` actually takes effect on macOS instead of being ignored by BSD `mktemp`.
- The generator refuses a personal profile or lockbox staging root before downloading the model, with an actionable message, instead of failing after the build when the sanitizer rejects the same path. The staging directory is also removed through a guard that rejects an empty, relative, root or unexpected path.
- The portable runtime sanitizer now makes a payload genuinely position independent: absolute install names left by wheel builds (delocation prefixes such as `/DLC`, conda prefixes such as `/opt/llvm-openmp/lib`, scratch build roots) become `@rpath/<name>`, and an absolute dependency that points inside the payload becomes `@loader_path/<relative>`. System library references are preserved. Dependencies resolved to a repaired library use loader-relative paths; duplicate library names receive distinct layout-scoped install identifiers.
- The sanitizer aborts, before rewriting anything, when an absolute non-system dependency cannot be located and verified inside the payload, matches more than one payload file, or resolves outside the runtime through a symlink. It never guesses a target by basename.
- The strict portability audit now reports an absolute reference that resolves to a file of the audited payload as `absolute_runtime_reference`, independent of the root prefix. A build root recorded under a scratch volume can no longer hide the defect behind a warning, and a dead absolute install name or dependency is a violation instead of a warning.
- The `otool` parsing layer no longer treats the per-architecture header of a universal Mach-O as a dependency, keeps paths that contain spaces intact, and reports the install name of every architecture slice. The previous parser produced phantom absolute dependencies equal to the file itself, which is why the previous candidate blamed self-references that do not exist in the payload.

### New and improved

- This candidate includes the iPhone Companion work prepared in the unpublished 2.0.37 attempt: persistent encrypted pairing and revocation, conversation-history requests with validated citations, measured speaker turns and conservative attribution, and clearer runtime readiness. The latest stable baseline remains 2.0.36.

- The Pyannote staging and relocation behavior is covered by contract tests that build real Mach-O fixtures, sanitize them, move the whole tree to another path and then load it through the dynamic loader and `ctypes`; by tests that stage on macOS with and without spaces in `TMPDIR`; and by tests that keep refusing profile, pairing, escaping and missing-dependency cases.
- The sanitizer plans every load-command change before it writes any, so a failed repair cannot leave a half-sanitized, half-signed tree behind, and a second run on an already sanitized payload is a byte-level no-op.
- The generator has a `--stage-dir-probe` mode that resolves, creates and removes the real staging directory without downloading anything, so the staging contract is testable in isolation.

### Compatibility

- The product identity remains `com.sbobino.desktop`, and updater artifacts stay signed with the configured key and published through the `public` release profile.
- Native targets remain macOS arm64 and macOS Intel, plus the Windows x86_64 installer. The Windows packaging path is unchanged by this release.
- Existing settings, transcripts, artifacts, models and compatible runtimes are preserved across the update.
- Pyannote is rebuilt natively from the declared Python 3.11 and pyannote.audio inputs. The local release checks exercise both the official universal2 framework and Homebrew Python, validate the generated payload after relocation, and record source hashes. Per-platform runtime versions are determined by each native build rather than copied from a test app.
- The official build uses its own application identity, so a pairing created against a LAN test build does not carry over: pair the iPhone once more through the Companion panel and do not copy tokens, certificates or keys from a test profile.
- Companion is opt-in and off by default; no firewall, VPN or network rule is changed by installing or updating this version.

### Known issues

- Companion is a LAN feature of the desktop app. This release does not ship an App Store build of the iPhone companion and does not guarantee a remote relay outside the local network.
- Local AI generation depends on the Mac: Apple Foundation Models need supported hardware, and Qwen needs a separately installed local Ollama runtime. No iPhone model is bundled or required.
- macOS packages are signed ad hoc and are not notarized unless Developer ID secrets are present in the release environment; Windows installers remain unsigned. Only updater artifacts use the configured updater signature.
- Native macOS Intel and Windows artifacts require their own official distribution and portability proofs before promotion. Local Apple Silicon and Rosetta process-mode checks do not certify those native runtime payloads.
- The inactive torchcodec FFmpeg variants still report unresolved `@rpath` dependencies in the audit warnings; only the bundled variant is imported at runtime.
- Native iPhone pairing, AI generation and interactive accessibility flows are verified on candidate builds, not on the public artifacts; the public-asset checks remain the release gate.
