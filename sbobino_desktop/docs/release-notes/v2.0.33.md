## Sbobino 2.0.33

### Fixes

- Live startup now uses the native engine and model actually selected by readiness checks; a configured Parakeet file model no longer mislabels the Whisper Live session.
- Runtime, model, and Pyannote installation wait for an immediate completion event safely and stop waiting after a bounded timeout. The original installation error remains visible if the final refresh also fails.
- Provisioning results stay in their owning settings panel, and a failed Pyannote repair can report that the previous installation remains available.
- A denied secure-storage initialization now returns a startup error instead of panicking.
- Windows runtime packaging uses an available, SHA-256-verified FFmpeg archive and recognizes the Windows system DLLs imported by that build.

### New and improved

- Added focused regression tests for immediate, missing, failed, cancelled, and timed-out provisioning events, plus secure-storage initialization failure.
- Added required GitHub CI jobs for native Rust tests on macOS arm64, macOS Intel, and Windows x86_64; Linux continues to run the supported crate and frontend checks.

### Compatibility

- Existing settings, transcripts, models, and compatible Pyannote installations remain in place.
- Live uses the native Whisper selection; configured Parakeet preferences continue to apply to file transcription.
- Native package targets remain macOS arm64, macOS x86_64, and Windows x86_64.

### Known issues

- GitHub-hosted tests cannot prove microphone, GPU, accessibility, or every user-installed runtime on a desktop session; those flows require separate native package validation before promotion.
