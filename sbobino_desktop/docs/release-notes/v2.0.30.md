## Sbobino 2.0.30

### Fixes

- Stabilized managed Parakeet readiness by treating the `parakeet-batch-json` worker as a required packaged runtime component, with actionable diagnostics when the worker is absent or cannot be started. (`crates/infrastructure/src/lib.rs`, `apps/desktop/src-tauri/src/commands/runtime.rs`)
- Made Pyannote runtime swaps recoverable after interruption: staged and backup directories are owner-marked, abandoned transaction paths are cleaned safely, and a failed replacement can roll back without discarding the last working install. (`apps/desktop/src-tauri/src/commands/provisioning.rs`)
- Fixed the macOS Pyannote false failure that requested FFmpeg libraries for every optional TorchCodec core. Sbobino now accepts the complete ABI variant actually bundled and still requires the real import/pipeline smoke before marking diarization ready. (`crates/infrastructure/src/lib.rs`)
- Fixed Pyannote setup remaining visually stuck at step 2/2 after a terminal validation error; failure and cancellation now clear progress and keep transcription available without diarization. (`apps/desktop/src/App.tsx`)
- Added isolated Windows DLL loading for the embedded Python/PyTorch/TorchCodec stack so a clean Windows installation does not depend on host search paths. (`apps/desktop/src-tauri/src/commands/provisioning.rs`)

### New and improved

- Added receipt-only verification for existing Pyannote installations. A compatible runtime that predates the durable receipt can now be checked in place and recorded without downloading the large runtime and model archives again. (`apps/desktop/src-tauri/src/commands/provisioning.rs`)
- Kept engine readiness scoped to the selected managed engine while requiring the complete Parakeet path, including its batch worker, whenever Parakeet is selected. (`apps/desktop/src-tauri/src/commands/runtime.rs`, `crates/infrastructure/src/lib.rs`)
- Tightened candidate packaging so updater metadata, runtime manifests, Pyannote manifests, checksums, hosted platform proofs, and these reviewed notes all belong to the same versioned candidate. (`scripts/assemble_local_release.sh`, `scripts/generate_release_candidate_metadata.py`, `.github/workflows/release.yml`)

### Compatibility

- Existing settings, transcripts, models, timelines, API keys, and compatible Pyannote installations remain readable. Missing or invalid receipts trigger verification or repair guidance rather than silently replacing a working installation.
- Candidate packages continue to target Apple Silicon macOS (`aarch64-apple-darwin`), Intel macOS (`x86_64-apple-darwin`), and Windows (`x86_64-pc-windows-msvc`). The candidate ships architecture-matched speech runtimes, the Parakeet batch worker, and Pyannote runtime/model assets.
- Release validation continues to use standard free GitHub-hosted runners (`macos-15`, `macos-15-intel`, and `windows-2025`).

### Known issues

- v2.0.30 is prepared as a prerelease candidate; promotion to Latest remains blocked until every required installer, updater signature, runtime/Pyannote asset, checksum, and hosted platform proof passes its corresponding gate.
- CPU-only Parakeet files and Pyannote deep checks can take a long time on standard hosted runners. Whisper live remains subject to the measured hardware capability and may return a preflight rejection with the recording preserved for file transcription.

### Refs

- Release range: `v2.0.29..v2.0.30`.
- Evidence required for this candidate: current managed-runtime and Pyannote provisioning changes, the candidate packaging gates, and hosted ARM64, Intel, and Windows proof assets generated by the release workflow.
