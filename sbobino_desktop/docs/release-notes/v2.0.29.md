## Sbobino 2.0.29

### Fixes

- Prevented Whisper live from entering an invisible backlog: the packaged runtime now measures both the median and peak inference time before capture and stops with an actionable file-transcription fallback when realtime cannot be sustained. (`scripts/patches/whisper-stream-backlog.patch`, `scripts/run_whisper_live_replay.py`; `a28053a`)
- Preserved the captured audio and completed chunks during slow-hardware recovery, with lossless WAV frame checks and no replay or percentage reset. (`scripts/release_macos_whisper_live_smoke.sh`; `a28053a`)
- Made Core ML provisioning verifiable and repeatable by pinning the Apple Silicon encoder archive, checking its compiled model and weights, and recording its digest in the runtime proof. (`crates/domain/src/whisper_live_model.json`, `apps/desktop/src-tauri/src/commands/provisioning.rs`; `a28053a`)
- Corrected the release gate so authentic preflight rejection proofs validate the measured peak as well as the median, require multiple samples, and use the same checks on macOS and Windows. (`scripts/promote_candidate_release.sh`; `a28053a`)
- Fixed the hosted Intel Parakeet/Pyannote smoke to invoke the packaged FFmpeg binary explicitly, so a clean runner no longer depends on a system FFmpeg installation. (`scripts/release_intel_pyannote_parakeet_smoke.sh`, `crates/infrastructure/tests/parakeet_real_service_smoke_tests.rs`; `083a1a3`)
- Fixed the Intel long-file watchdog to observe the same physical `/private/var` worker path that Rust launches after macOS canonicalization; failed live smoke runs now retain compact preflight/recovery diagnostics for safe triage instead of hiding the cause. (`scripts/smoke_parakeet_real.sh`, `scripts/release_macos_whisper_live_smoke.sh`; `4e2d508`)

### New and improved

- Added a hardware-aware live readiness profile: fast Apple Silicon can run Whisper live with Core ML, while hosted or older CPU-only machines receive a clear preflight result before any audio is captured. The local ARM64 package proof measured first preview 0.58 s, P95 preview latency 1.15 s, backlog P95 0.15 s, zero dropped/missing/duplicate segments, and Core ML loaded.
- Added a pinned Core ML encoder manifest and architecture-specific runtime hashes so packaged ARM builds cannot silently fall back to an unvalidated encoder. (`crates/domain/src/settings.rs`, `crates/domain/src/whisper_live_model.json`; `a28053a`)
- Switched hosted Apple Silicon validation to the standard free `macos-15` runner and kept Intel validation on `macos-15-intel`; both now attest zero-capture rejection when their measured CPU profile is not realtime-capable. (`.github/workflows/arm-runtime-validation.yml`, `.github/workflows/release.yml`; `a28053a`)
- Extended the native validation matrix with real packaged proofs: ARM Core ML live replay, Windows installer/GUI/runtime smoke, Intel Whisper live preflight/recovery, and the 65-second Intel Parakeet CPU plus Pyannote path. The Intel Parakeet run completed in 3620.81 s with 1006.25 MiB peak worker RSS and passed its metadata persistence test.

### Compatibility

- Settings, transcripts, models, timelines and API keys remain compatible with v2.0.28. The release targets macOS Apple Silicon, macOS Intel x86_64 and Windows x86_64; CPU remains available as an explicit device choice and Auto uses acceleration when the packaged runtime supports it.
- AI providers and Pyannote remain optional to the transcription path. If realtime preflight fails, Sbobino preserves the audio and offers file transcription rather than silently returning a delayed or incomplete live transcript.
- The native checks use only standard GitHub-hosted runners (`macos-15`, `macos-15-intel`, `windows-2025`); no larger or paid runner is required for the release gate.

### Known issues

- The standard hosted ARM and Intel runners are intentionally reported as non-realtime for Whisper live when their measured inference exceeds the one-second budget. This is a truthful capability result, not a failed transcription: use a faster local device or the preserved file recording. Intel Metal acceleration is not claimed because it was not exercised on physical Intel hardware.
- The public release gate validates the packaged 65-second Intel Parakeet file path and Pyannote deep smoke; very long CPU-only Parakeet jobs can take a long time on hosted Intel hardware.
